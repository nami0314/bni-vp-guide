# ローンチ進捗ボード（BNI福岡博多リージョン）

BNI福岡博多リージョンの新チャプター立ち上げ（ローンチ）を、毎日の進捗が見える形で管理する仕組み。
Googleスプレッドシート「ローンチチーム管理表」＋ Google Apps Script（GAS）で動く。
使う人はOM（オペレーションマネージャー・川嶋）、LD（ローンチディレクター）、担当メンバー（見込み客をリストアップした人）。プログラマーではないので、説明は専門用語を避けて日本語（です・ます）で。

## 構成

- `src/main.gs` … 管理表側の機能（メニュー、編集時の自動入力、入会後行動リストの自動作成、アラートメール、ローンチ追加）
- `src/site.gs` … 進捗ボード（Webアプリ）のサーバー側。`doGet` と `web*` 関数、利用者シート、個人用リンク
- `src/page.html` … 進捗ボードの画面（HTML/CSS/JSを1ファイルに）。`__BOOT__` に起動情報が差し込まれる
- `build.mjs` … 上の3つを **`dist/Code.gs` 1ファイル** にまとめる（page.html は `PAGE_HTML_LINES` 配列として埋め込む）
- `dist/appsscript.json` … GASの設定（タイムゾーン、Webアプリの公開設定）
- `tests/server.test.cjs` … GASのサービスを模擬してサーバー関数を動かすテスト
- `tools/preview.mjs` … 画面をローカルのブラウザで確認するためのプレビュー作成
- `tools/build_workbook.py` … 管理表（xlsx）を作ったスクリプト（シート構成の正本。openpyxl）
- `docs/launch_team_management_v5.xlsx` … 管理表のひな形

## よく使うコマンド

```
node build.mjs                 # dist/Code.gs を作る
node tests/server.test.cjs     # テスト（先に build）
node tools/preview.mjs         # tests/out/preview_om.html / preview_tan.html を作る → ブラウザで開いて見た目確認
npx clasp push                 # dist/ をApps Scriptへ反映（.clasp.json が必要。README参照）
```

コードを変えたら必ず「build → test」を通してから渡す。画面を変えたら preview で見た目も確認する。

## 守ること

- **納品物は `dist/Code.gs` の1ファイル**。利用者は「貼り付けるだけ」で使いたい。HTMLファイルを別に分けない。`dist/Code.gs` は直接編集せず、`src/` を直して build する
- 設定値は `main.gs` 先頭の `CONFIG` と `site.gs` の `SITE` に集める
- シートの列は `C`（CCS追っかけ）、`T`（入会後行動リスト）、`U`（サイト利用者）の定数で参照する。列番号を直書きしない。データは5行目から（`FIRST_ROW`）、4行目が見出し
- CCS追っかけの A・P・S・W 列、行動リストの J 列は数式。**上書きしない**（`webAddProspect` は B〜O 列と R・T・U・V 列だけに書く）
- スプレッドシートは `ss_()` で取得する。Webアプリから呼ばれた時は `SpreadsheetApp.getActive()` が null になるため、`CONFIG.SPREADSHEET_ID` → 保存済みIDの順で開く
- `SpreadsheetApp.getUi()` はメニューから呼ばれる関数だけで使う（`web*` 関数やトリガーから呼ぶとエラー）
- `google.script.run` は Date を返せない。日付は `ymd_()` で `yyyy/MM/dd` の文字列にして渡す
- 書き込む `web*` 関数は `withLock_` で囲み、最初に `auth_(key)` と権限チェックをする
- 権限：OM＝全ローンチ／LD＝自分のローンチ／担当＝自分の見込み客と、その人の入会後タスク。**画面で隠すだけでなく、サーバー側で必ず絞る**
- 誰が開いたかは個人用リンク（`?k=キー`）で判定する（Gmail同士ではアクセス者のメールを取得できないため）
- メールは無料Gmailの1日100通が上限。送信前に `MailApp.getRemainingDailyQuota()` を確認し、優先順（OM→LD→担当→本人）で送る
- `CONFIG.TEST_MODE` が true の間は、アラートはOMにだけまとめて届く。既定値は true のままにする
- LINEへの自動送信はしない（公式アカウントの無料枠では足りないため、メールのみと決定済み）
- 見込み客の氏名・電話番号などの個人情報を、テストデータやコメント、ログに書かない。テストは架空の名前で

## 業務ルール（RCS ローンチ方針）

- プリコア人数は「申込書・振込控え（入金）・プリコア同意書」の3つが揃った人だけを数える
- フェーズ1は6週間、フェーズ2は4週間が期限（設定シートで変更可）。期限内に未達なら全員と面談し、①継続 ②他チャプター紹介 ③返金 の3択
- フェーズ3以降はメンバー都合の返金不可
- 新メンバーには必ずウェルカムコール。1年目メンバーにはベーシック受講を確認
- 毎週月曜9:00にウィークリーローンチミーティング。ダッシュボードはこの場で使う

## シート構成（管理表）

使い方／📊ダッシュボード／全体管理／週次推移（10/5スタート・13週）／CCS追っかけ／担当別CCS／入会後行動リスト／入会後進捗／日次ログ／各LDシート（シート名＝LD名）／行動マスタ／通知先／設定／サイト利用者／アラートログ

- ローンチの名前＝LDシートの名前＝ダッシュボードA列＝設定のLD一覧＝通知先A列。この5つが一致している前提で集計している
- LDシート：B4 管轄エリア、B6 チャプター名、B8 初回定例会目安、B24 現フェーズ、B25 フェーズ開始日、B26 目標人数、B27 今週の課題
- 設定シート：A列の項目名をGASが読んでいる（名前を変えない）。「LD一覧」の右隣の「声かけ目標（1日）」列は、LD一覧と同じ行のローンチの目標（空欄なら `SITE.DAILY_GOAL`＝10）

## デプロイの注意

- Webアプリは「デプロイを管理 → 鉛筆 → 新バージョン」で更新する。「新しいデプロイ」だとURLが変わり、配布済みの個人用リンクが使えなくなる
- `clasp push` はApps Script側のファイルを `dist/` の内容で置き換える。push しただけではWebアプリは古いままなので、続けて新バージョンのデプロイが必要
